# ADR-004: Canonical Indexed Answer Protocol over Raw JSON and Semicolon Streams

## Status
Accepted

## Date
2026-10-08

## Context
Normal (non-programming) assessments on the IITM portal consist of MCQ, MSQ, Numerical, and Text questions distributed across paginated Angular chips. Students collaborating with AI assistance or transferring answer keys between sessions require a standardized answer interchange protocol.

Historical approaches evaluated in the project included:
1. **Raw JSON Payloads**: Requiring complete JSON structures (`{"acadrix": 1, "fp": "...", "answers": [...]}`).
2. **Legacy Semicolon Streams**: Flat semicolon-separated key-value pairs (`1:A;2:B,C;3:1000`).

Both formats presented severe operational friction:
- **JSON Fragility**: LLMs frequently introduce formatting errors (trailing commas, unescaped quotes in explanation text, invalid backslash escapes). A single JSON parse error invalidates the entire answer key.
- **Semicolon Collisions**: Semicolons are common punctuation in code snippets, formulas, and natural language explanations. Semicolon-delimited streams break whenever an answer contains an unescaped `;`.
- **Multiline Text Inability**: Semicolon streams cannot natively represent multiline text responses without complex escaping rules.

## Decision
Establish the **Canonical Indexed Answer Protocol** (`ANSWER_PROTOCOL.md`) as the primary interchange format:

```text
1: A
2: B,C
3: 42.5
4: <<<
The quick brown fox
jumps over the lazy dog.
>>>
5:
```

### Protocol Grammar & Rules:
1. **Line-Oriented Records**: `<question-number>: <answer-text>`.
2. **First-Colon Splitting**: Splitting occurs strictly on the *first* colon. Colons inside answers (e.g. `4: Ratio is 3:4`) are preserved verbatim.
3. **Multi-Select (MSQ)**: Comma-separated option letters (`2: B,C`). No brackets required.
4. **Multiline Blocks**: Enclosed by `<<<` and `>>>` delimiters on dedicated lines. All internal newlines, punctuation, and formatting are preserved.
5. **Empty / Unanswered Markers**: Explicit `N:` line indicates an unanswered question (`status: "missing"`).
6. **Canonical Numerical Normalization**:
   - `42.50` normalizes to `42.5`.
   - `-0` normalizes to `0`.
   - Rejects non-canonical representations (leading signs `+5`, trailing decimals `42.`, scientific notation `1e3`).
7. **Document Fingerprint Verification**: In JSON payload mode, payloads are verified against an 8-character hash (`assignmentFingerprint`) computed from question stems and options (deliberately excluding review/answer state).

### Backward Compatibility:
The parser (`src/bridge/parser.js`, `answer-stream.js`) maintains backward compatibility:
- Automatically detects JSON payloads and legacy semicolon streams.
- Normalizes all input into the canonical indexed format upon export or re-serialization.

## Alternatives Considered

### Alternative 1: Strict JSON-Only Protocol
- *Pros*: Built-in browser parsing (`JSON.parse`).
- *Cons*: High error rate from LLMs on mobile or quick-prompt interfaces; difficult for humans to write or edit manually.
- *Reason for Rejection*: Poor usability for manual entry and frequent model formatting failures.

### Alternative 2: CSV / TSV Format
- *Pros*: Tabular format familiar to spreadsheet users.
- *Cons*: Requires complex CSV quoting rules (RFC 4180) to handle commas in MSQ options or text answers.
- *Reason for Rejection*: Quoting rules add friction and are inconsistently generated by LLMs.

## Consequences
- **Positive**: Extremely resilient: LLMs generate the indexed format with near-zero syntax errors.
- **Positive**: Human-readable and editable in plain text editors.
- **Positive**: Native support for multiline responses and internal punctuation.
- **Positive**: Deterministic parsing and type validation across all question types.
- **Negative**: Custom parser required (`src/bridge/answer-stream.js`), though thoroughly tested in unit suites.
