# Normal-assignment answer protocol

The canonical interchange format for normal (non-programming) assessment answers is one question-indexed record per line:

```text
1: A
2: B,C
3: 1000
4: here
```

The question number is one-based. The first colon separates the number from the answer; later colons belong to the answer. Multiple-choice answers use the option letter, and multi-select answers use comma-separated option letters. Numerical and other answer values are text following the colon.

## Multiline and missing answers

A multiline answer uses `<<<` and `>>>` delimiters:

```text
4: <<<
A response spanning
multiple lines.
>>>
```

An empty indexed record such as `5:` indicates no answer. Questions without a record are also treated as unanswered by the parser.

## Validation and application

`src/bridge/answer-stream.js` serializes and parses answer records. `src/bridge/parser.js` validates records against the current assignment, including question numbers, available options, answer types, and numerical normalization. The Reader shows valid, missing, or invalid suggestions for review. Applying answers is a separate, user-triggered action; it does not submit the assessment.

Prompts generated by `src/bridge/prompt.js` ask for this indexed form. A basic prompt response should look like the first example above, not a positional list or HTML fragment.

## Compatibility

The parser retains legacy semicolon-separated and supported JSON payload parsing for compatibility. These are not the canonical serialization format; new prompts and serialized answer streams use indexed records.
